# form-rewind の実装メモ

「フォームキーパー」(Chrome ウェブストアの入力自動保存拡張。開発元のリポジトリが無く、
自動更新で中身が変わるのが不安で作り直した) の自動保存・差分・固定と、
「AutoFormer+」の「すべてのフィールドを保存」+オートロードを1つにまとめたもの。
どちらもコードは参考にしただけで写していない(ライセンス不明)。機能一覧は README.md。

## ファイル構成

```
manifest.json      MV3。permissions は storage / unlimitedStorage / alarms のみ。CSP で connect-src 'none'
src/settings.js    設定の既定値。モジュールにせず globalThis に置く(content script・SW・画面の全部から読むため)
src/fields.js      欄の列挙・値の読み書き・保存した欄との突き合わせ。DOM を触るのはここだけ
src/page-ui.js     ページ右下のバナーと通知(shadow root)
src/content.js     各フレームの本体。自動保存・バナー・復元/差分の受け口・すべてのフィールドを保存・オートロード
src/background.js  service worker。保存の規則・送り主の検証・復元の振り分け・掃除・バッジ・ショートカット
src/db.js          IndexedDB(snapshots と fieldSets)
src/popup.*        ポップアップ(一覧・差分・固定・フィールドの保存)
src/options.*      設定画面
src/saved-fields.* 「すべてのフィールドを保存」の中身を表で見せて編集する画面
test/e2e.js        E2E。test/fixture.js がテスト用サーバ(8766)
icons/icon.svg     アイコンのソース。PNG は rsvg-convert で書き出す
```

## データ

| 置き場所 | 中身 |
| --- | --- |
| IndexedDB `form-rewind` / `snapshots` | 自動保存の履歴。`pageKey`(そのフレームの origin+pathname)・`topKey`(タブの origin+pathname)・`domain`(タブのホスト)で引く。固定は `pinned / pinName / pinScope` |
| IndexedDB `form-rewind` / `fieldSets` | すべてのフィールドを保存の中身。キーは origin、`entries` は「フォーム名@タグ:type@name」→ 値 |
| `chrome.storage.local` `settings` | `maxPerPage` / `retentionDays` / `showToast` / `autoload` / `pausedDomains` |

pageKey にクエリ文字列を含めない(`?id=` 違いのページは同じ履歴に入る)。元のフォームキーパーと同じ割り切り。

## 暗号化しない理由

元のフォームキーパーは AES-GCM で暗号化していたが、**マスターパスワード未設定時は鍵を
`chrome.storage.local` に平文で置いていた**。暗号文と同じプロフィールのフォルダにあるので、
ディスクを読める相手には鍵ごと読まれる。他サイトや他の拡張は元から拡張の IndexedDB を読めない。
つまりパスワードなしの暗号化は難読化にしかならない。パスワード必須にすると、ブラウザを
再起動するたびにロック解除が要り、「クラッシュ後に取り戻す」という一番の用途とぶつかる。
ユーザーと相談して **暗号化しない・ディスクは OS(FileVault)に任せる** と決めた(2026-10-17)。

同じ相談で、保存しないものは**パスワード欄だけ**と決めた。カード番号・ワンタイムコードなどは
保存する(使う人の判断に任せる)。hidden・file・ボタンは値を入れられないので対象外。
検索ボックスは安全のためではなく、検索するたびに履歴ができて全サイトでバナーが出るのを防ぐために外している。

## 欄の特定と突き合わせ(fields.js)

- 位置は XPath ではなく `tag[n]/tag[n]/...` の自前のパス。shadow root をまたぐ所に `#shadow` を挟む。
  `document.evaluate` は ShadowRoot を文脈にしたときの挙動が怪しいので、子要素を自分でたどって解決する。
- 復元時は **パス → 自動生成でない id → name(+同じ name の何番目か) → ラベル** の順で探す。
  DOM が組み変わったページ(SPA の再描画)でもたいてい当たる。
  id が自動生成っぽい(`:r1:`・長い16進・数字3桁以上など)ときは id を信用しない。
- 値の書き込みは React 対策でプロトタイプの `value` setter を呼んでから input/change を送る。
- **チェックボックス・ラジオは `click()` で切り替える。** `checked` を書いてから click を送ると
  React 側で二重に反転する。
- contenteditable は innerHTML で保存し、書き戻すときは script/iframe/on* 属性などを落としてから入れる。

### 初期値から変わったか(isChanged)

保存するかどうか・オートロードで空欄とみなすかに使う。**`selected` 属性が1つもない `<select>` は
`defaultSelected` が全部 false**になるので、素直に `selected !== defaultSelected` を比べると
「先頭が選ばれているだけ」で変更あり扱いになる(オートロードがセレクトを入力済みとみなして
飛ばしていた)。default が無いときは「単一選択なら先頭」を初期値として比べる。

## 自動保存の規則(background.js の saveSnapshot)

- content 側は input/change から 1 秒待って保存(打ち続けても 10 秒ごとに必ず)。
  タブを隠したとき・pagehide でも書き出す。
- **直前の保存から 60 秒以内なら新しい履歴を足さずに上書き**する。打鍵ごとに履歴が増えないように。
  ただし次のときは別の履歴にする:
  - 最初の保存から 10 分過ぎた(長時間書き続けても、途中の版が残るように)
  - **どこかの欄が空になった、または 10 文字以上減った**。全選択して消した直後の状態で、
    消す前の履歴を上書きしてしまうのを防ぐための規則。元のフォームキーパーにはなかった
  - 復元の直前に今の入力を保存したもの(`keep`)
- 前回と同じ内容なら何もしない。
- 拡張機能自身が値を書き込んでいる間(復元・読み込み・オートロード)は `writing` を立て、
  入力イベントを保存のきっかけにしない。オートロードで履歴が作られるのを防ぐ。

## 送り主の検証

ページ(content script)から受けるのは `CONTENT_MESSAGES` の6種類だけ。どれも
**送り主のオリジンと、メッセージ中の pageKey / origin が一致するか**を見る。
これがないと、あるサイトのページが他サイトの履歴や保存したフィールドを読めてしまう。
一覧・差分・削除・固定などは拡張機能のページ(ポップアップ・設定画面)からだけ受ける。

## iframe

- content script は `all_frames: true`。iframe の保存は `sender.tab.url` から最上位の topKey を付ける。
- バナーは最上位のフレームだけが出し、フレームごとの最新をまとめて数える。
- 復元・差分は、最上位の履歴なら `frameId: 0` に、iframe の履歴なら全フレームへ送って
  **pageKey が合うフレームだけが応答**する(`targetPageKey`)。`webNavigation` 権限を足さないため。

## すべてのフィールドを保存 / オートロード

AutoFormer+ を読んだうえでの仕様(2026-10-17 にユーザーと決めた):

- **サイト(オリジン)ごとに1組・欄ごとに上書き。** キーは `フォーム名@タグ:type@name`。
  URL を含めないので、同じ name なら同じサイトの別ページでも入る。name も id も無い欄は
  ラベル、それも無ければ「ページ+パス」をキーにする(AutoFormer+ は全部 `unknown` に潰れていた)。
- ラジオはチェックされたものだけ保存し、同じグループの古い記録は消す(残すと読み込みで勝ち負けが決まらない)。
- **オートロードは初期値オン、ただし空欄にだけ・1つの欄に1回だけ入れる。** AutoFormer+ は
  フォームが足されるたびに全欄を上書きするので、打った内容が後から消える。
  後から描かれる欄は MutationObserver で拾う(入力欄を含むノードが足されたら 300ms 後に読み込み)。
- 手動の「すべて読み込む」は入力済みの欄も上書きする。Shift を押しながらだと空欄だけ。
- 右クリックの「この欄だけ保存/読み込み」は入れていない(ユーザー判断で不要)。
- ショートカットは3つ登録してあるがキーは割り当てない。名前の先頭の `01_` などは
  `chrome://extensions/shortcuts` の並び順をそろえるため。

### 編集画面(saved-fields.*)

Lightning AutoFill の Form Fields 画面(ルールを表で並べ、行ごとに直接編集・保存/元に戻す)に倣った
(2026-10-17 ユーザー要望。ポップアップからは何が保存されていて自動で入るのか分からなかったため)。

- 列は 種類・項目・値・自動・削除。項目名はラベル、無ければキーの name。
  **ラジオだけは name を項目名にする**(ラジオのラベルは選択肢の名前で、設問が分からないため)。
  ラジオの「どれを選ぶか」は選択肢の一覧を保存していないので編集できない。ページで選び直して保存し直してもらう。
- セレクトは表示名で編集し、`value` と `text` の両方に入れる。読み込み側は value → 表示名の順に選択肢を探すので当たる。
- **「自動」を外すと `entry.auto = false`。** オートロードは飛ばし、手動の読み込みでは入れる。
  ページで「すべてのフィールドを保存」し直すと entries が丸ごと差し替わるので、SW の saveFieldSet で
  **既存の `auto: false` を引き継ぐ**(引き継がないと保存し直すたびに外した設定が消える)。
- 編集は draft に溜めて「保存」でまとめて書く。**開いた時点の updatedAt を送り、DB と違えば書かない**
  (`PUT_FIELD_SET` が CONFLICT を返す)。開いている間にページ側で保存された分を黙って消さないため。
  「元に戻す」は DB から読み直すので、競合のあとに最新を取り直す操作も兼ねる。
- `db.updateFieldSet` の更新関数が null を返したら put しない(競合時用)。
- 未保存のままサイトを切り替えさせない(`confirm()` は使わない)。閉じるときは beforeunload で止める。
- ルールの新規追加は入れていない。キーは「フォーム名@タグ:type@name」の完全一致なので、
  手で書かせると form 名や type の違いで当たらないものができやすい。

### エクスポート / インポート

- 形式は `{ format: "form-rewind-fields", version: 1, exportedAt, sites: [{ origin, updatedAt, entries }] }`。
  全サイトを1ファイルにする。ダウンロードは Blob + `a[download]`(`downloads` 権限は要らない)。
- インポートはサイトごとに **統合**(同じキーはファイル側で上書き、無いキーは残す)。丸ごと置き換えにしないのは、
  別の端末から持ってきたファイルで、こちらにしかない分を消さないため。
- ファイルは手で書き換えられうるので、SW の `cleanImport` で検査し直す。format / version が違う、
  origin が http(s) のオリジンそのものでない、項目の tag が大文字のタグ名でない、値が1つも無い、
  のどれかがあれば**全体を読み込まない**(一部だけ入るのは分かりにくい)。項目は知っている属性だけを拾い直す。
- 未保存の編集があるあいだは両方のボタンを無効にする(エクスポートに編集が入らない・インポートと競合する)。

### バッジ

- 読み込んだ項目数を出すのは AutoFormer+ の仕様に合わせた(2026-10-17 ユーザー要望)。色は最初 AutoFormer+ と同じ赤に
  したが、ユーザーの希望で青(`#1a73e8`、履歴ありの ● と同色)に変えた。数字か ● かで見分けがつく。
  履歴ありの青い ● より優先し、件数が 0 なら ● に戻る。
- content 側は「このページを開いてから読み込んだ欄」を WeakSet で持ち、**同じ欄は1回だけ数えた累計**を
  `FIELDS_LOADED` で送る。手動の読み込みとオートロードの後追いで同じ欄を二重に数えないため。
- SW は `chrome.storage.session` に `loaded:<tabId>:<frameId>` で**フレームごとに別キー**で置き、表示時に足す。
  1つのキーに足し込むと、同時に報告してくる iframe と本体で読み書きが競合する(fieldSets で一度踏んだのと同じ形)。
  SW が止まっても消えないよう、メモリではなく session ストレージにしている。
- `tabs.onUpdated` の `status: "loading"` でそのタブの分を消す(=ページを開き直したら数え直し)。

**AutoFormer+ との違いで大事な点:** AutoFormer+ は保存先がそのサイト自身の `localStorage` で、
パスワード欄も除外していない。そのサイトの JS(広告・解析タグも)から読める。
こちらは拡張の IndexedDB に置くのでサイトからは読めない。

### ハマった点: 同じオリジンの iframe と本体が同時に保存する

ポップアップの保存ボタンはタブの全フレームへ送るので、同じオリジンの iframe と本体が
ほぼ同時に `SAVE_FIELD_SET` を投げる。「読む → 混ぜる → 書く」を別々のトランザクションで
やっていたら、後から書いた方が先の分を消した(E2E で iframe の欄しか残らなかった)。
`db.updateFieldSet` で読みから書きまでを1つの readwrite トランザクションにして解決。

## ポップアップ

- 履歴の要約は「文字の入った欄を ` / ` でつないだもの」。最初の欄だけだと名前しか見えず、
  履歴どうしの区別がつかなかった。
- 差分は、どちらも空(またはオフ)のままの欄を出さず、違う行を上に寄せる。
- `display` を指定した要素に `hidden` 属性を付けても消えない。`common.css` で
  `[hidden] { display: none !important; }` にしている。
- 消す操作(フィールドの消去・履歴の削除)は `confirm()` を使わず、2回押させる。

## バナー

開いたページに、保存した最新の内容と違う値の欄が1つでもあるときだけ出す
(送信後に戻ってきたときや、サーバが値を入れて返すページで毎回出ないように)。
フォームを後から描くページのため、欄が1つも見つからなければ 1.5 秒・4 秒後に見直す。
オートロードを先に済ませてから判定する。shadow root を open にしているのは E2E から押すため。

## E2E

```sh
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
npm test
```

- Brave Browser Nightly を `--load-extension` で起動する(通常の Chrome は無視する)。
- ポップアップは Playwright から開けないので、`popup.html` を普通のタブで開き、
  `chrome.tabs.query` だけ差し替えて対象タブで開いたことにする(`sendMessage` は本物を使う)。
  `window.close` も差し替える。
- IndexedDB は service worker から直接読む。**バージョン付きで開き、`onupgradeneeded` なら
  abort する**こと。拡張より先にテストが空の DB を作ると、拡張側の `onupgradeneeded` が二度と走らない。
- テストデータは架空の値だけを使う(実在の名前・メールを書かない)。
